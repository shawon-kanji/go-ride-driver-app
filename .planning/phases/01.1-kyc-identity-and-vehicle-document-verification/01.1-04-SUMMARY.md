## Decisions Made
- `vehicle_id` presence is decided once via `isVehicleDocumentType` and spread conditionally (`needsVehicle ? { vehicle_id: vehicleId } : {}`) into both the upload-url and confirm payloads, so the key is genuinely absent (not `undefined`-but-present) for identity documents — verified in tests via the `in` operator, not `toBeUndefined()`
- Vehicle-scoped uploads with no `vehicleId` throw synchronously inside `mutationFn` before any network call, avoiding a wasted round trip to a request the backend would reject anyway
- `useKycStatusQuery` deliberately has no `refetchInterval`; refresh happens on mutation success (`['kyc']` prefix invalidation) and on screen focus only, per research's anti-pattern guidance (approval has no notification endpoint)

- **Found during:** Task 3
- **Issue:** Two compounding issues blocked Task 3 from reaching GREEN: (a) `@testing-library/react-native@14`'s `renderHook` is async (same as `render()`, already a documented convention in STATE.md) — without `await`, `result` was `undefined`, throwing `TypeError: Cannot read properties of undefined (reading 'current')` on every test; (b) once fixed, `npx jest src/features/kyc/api.test.ts` never returned — `createTestQueryClient()` zeroed `gcTime` for queries but not mutations, so a completed mutation's default 5-minute `gcTime` scheduled a real `setTimeout` that kept the Node process alive indefinitely, hanging every test run (and would have hung any future plan's mutation tests that reuse this shared test util)
- **Fix:** Added `await` before all five `renderHook(...)` calls in `src/features/kyc/api.test.ts`; added `gcTime: 0` to the `mutations` block in `createTestQueryClient()` in `src/test-utils/query-wrapper.tsx`
