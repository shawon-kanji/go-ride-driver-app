## Radii & Component Shape Contract

Locked values (README "Driver app" table, confirmed byte-for-byte against `Driver App.dc.html`'s
`:root` block — `--r:12px; --r-lg:16px; --r-pill:999px;`):

| Token | Value | Tailwind class to add | Replaces |
|-------|-------|------------------------|----------|
| `control` | 12px | `rounded-control` | current `rounded-md` (6px) — used for text inputs, banners, form-submit rectangular buttons |
| `card` | 16px | `rounded-card` | current `rounded-lg` (16px, coincidentally already correct value but wrong token name) — used for bordered card/list containers |
| `pill` | 999px | `rounded-pill` | current `rounded-full` (already 9999px, correct value, wrong token name) — used for status badges, avatar chips, action-bar CTAs, small utility buttons |

**Critical implementation note (RESEARCH.md Pitfall 1, confirmed not hypothetical):**
`src/theme/radii.ts` is dead code — `tailwind.config.js` never imports it. Wire these three keys into
`tailwind.config.js`'s `theme.extend.borderRadius` directly, then find-and-replace every
`rounded-md`/`rounded-lg`/`rounded-full` call site across `Button.tsx`, `Card.tsx`, `Badge.tsx`,
`Banner.tsx`, `Stepper.tsx`, `TextInput.tsx`, `Select.tsx`, `ConfirmDialog.tsx` (8 files, confirmed
by grep) with the new semantic names. Editing `theme/radii.ts`'s values alone changes nothing
visually.

**Button shape is NOT uniform across the app — this is a real design decision, not an oversight.**
Verified directly against the HTML: form-submission CTAs and confirmation/status CTAs use two
different shapes:

| Shape | Radius | Height | Used for (this phase) |
|-------|--------|--------|------------------------|
| Rect CTA | `rounded-control` (12px) | 48–54px | D01 `Sign in`, D02 `Continue`, D05 `Register vehicle` |
| Pill CTA (primary) | `rounded-pill` (999px) | 54–58px | D06 `Go online` (enabled + disabled state), D06 `Fix my licence photo` / blocker action, D07 `Switch vehicle`, D07 `Go online` |
| Pill CTA (utility, compact) | `rounded-pill` (999px) | 34–38px | D04 `Upload` / `Re-upload`, D05 header `+ Add`, D03 `Log out` (52px, wide) |

`Button.tsx` currently applies `rounded-md` unconditionally regardless of variant/screen — it
needs a `shape?: 'rect' | 'pill'` prop (default `'rect'`, matching current auth-screen usage) so
D06/D07 can request the pill shape without a new component. Do not silently make all buttons pill
or all buttons rect — both shapes are used deliberately in the same screen set.

## Spacing Scale

> **LOCKED DESIGN-SYSTEM FIDELITY OVERRIDE — do not re-flag or reduce.** The full spacing
> scale below (including non-multiple-of-4 values 10/14/18/22px) is confirmed pixel-for-pixel
> against the real, finalized design handoff (`design_handoff_go_ride/`) and is explicitly
> exempted from `gsd-ui-checker`'s generic `{4,8,16,24,32,48,64}` spacing cap. This exemption is
> recorded as a locked decision in `02-CONTEXT.md` under the **"Design-system fidelity override
> (added after UI-SPEC review, 2026-08-18)"** heading — read that section for the full rationale
> before flagging this dimension again. Any downstream checker/planner/auditor should cite that
> decision by name rather than re-opening this as a gap.

**Deviation from the standard 8-point scale is a locked, verified decision — not a gap to fix.**
The design handoff (README "Spacing") specifies a denser scale for this app: "4px base. Screen
gutter 16–22px. Card padding 14–16px. Gaps 8/10/12/14/16. Row min-height 52–60px. Primary buttons
54–60px tall; every hit target is at least 44px." Confirmed pixel-for-pixel against every
`padding`/`gap` value in the D01–D07 HTML. Use these values, not the generic 4/8/16/24/32/48/64
progression.

| Token | Value | Usage (verified against D01–D07) |
|-------|-------|-----------------------------------|
| xs | 4px | Label-to-value micro gaps (e.g. stat card number under eyebrow) |
| sm | 8px | Compact inline gaps (link rows, small icon+text pairs) |
| gap-sm | 10px | Row icon-to-label gap (menu row icon chip, avatar-to-name gap) |
| gap-md | 12px | Card internal item gaps, banner icon-to-text gap, footer button row gap |
| md | 14px | Compact row vertical padding (D04 document rows), card padding lower bound |
| lg | 16px | Default card padding, list-row horizontal padding, section-to-section gaps, screen gutter lower bound |
| xl | 18px | D07 sheet top padding |
| 2xl | 20px | Screen gutter (D03/D04/D05 headers and bodies) |
| 3xl | 22px | Screen gutter (D01/D02 body padding) |
| 4xl | 24px | Sheet/modal top corner radius companion inset (D07 sheet corners) |

Exceptions (explicit, from README):
- Every tappable hit target is at least 44×44px, even icon-only ones (back chevrons, dismiss buttons).
- Primary buttons are 54–60px tall (not the generic 44–48px control height).
- List/card rows have a 52–60px minimum height (D03 menu rows, D05 vehicle-card footer cells).
- Large-scale spacing (32/48/64px) is not exercised by any D01–D07 screen — no full-bleed empty
  states or major section breaks appear in this phase's scope; retain the existing
  `spacing.ts` xl:32 value only for screens outside this phase's retrofit list.

## Color

Driver app colours are **locked, not changing** — `src/theme/colors.js` is the confirmed source of
truth (README: "Taken from `go-ride-driver-app/src/theme/colors.js` — use that file as the source
of truth, not this table," and CONTEXT.md restates this explicitly). Verified 1:1 against the
handoff's own `:root` CSS variables (`--n*` → `neutral`, `--p*` → `primary`, `--g*` → `success`,
`--w*` → `warning`, `--d*` → `danger`).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `neutral-50` `#F9FAFB` (screens with a body list: D03/D04/D05/D06/D07) or `neutral-0` `#FFFFFF` (form-only screens: D01/D02) | Screen background |
| Secondary (30%) | `neutral-0` `#FFFFFF` cards/sheets/rows, bordered with `neutral-200` `#E5E7EB` hairlines | Card containers, list rows, bottom sheets, form fields |
| Accent (10%) | `primary-500` `#4F46E5` (tint `primary-50` `#EEF2FF`, pressed `primary-600` `#4338CA`) | See reserved-for list below — do NOT apply to all interactive elements |
| Destructive | `danger-500` `#DC2626` (tint `danger-50` `#FEF2F2`, text `danger-700` `#991B1B`) | Error banners, rejected-document markers/re-upload buttons, Log out button text/border only |

**Accent (`primary`) reserved for exactly these elements — verified against every primary-colored
element in D01–D07, nothing else:**
- Brand header chrome blocks (D01 sign-in header, D03 menu profile header)
- Primary CTA buttons: `Sign in`, `Continue`, `Fix my licence photo`
- Focused text-input border (2px `primary-500`)
- Links (`Create an account`, `Sign in`)
- Informational banner tint + icon (`primary-50` bg, `primary-600`/`primary-700` icon/text) — e.g. D02's "vehicle and documents come later" note
- Selected/active-state 2px border + tint on cards (D05 fully-approved vehicle card, D07 confirmed-vehicle card)
- Avatar/initials chip background tint (`primary-50` bg, `primary-700` text) — used on D06's profile chip; D03's header avatar chip uses translucent white instead (`rgba(255,255,255,0.2)` on the indigo header, not a token — leave as an opacity overlay, not a new color)

**Explicit non-primary CTA colors (do not default these to primary — verified per-button):**
- `Register vehicle` (D05): `neutral-900` `#111827` background, white text — deliberately NOT primary, visually distinct from the auth-flow primary CTAs
- `Go online` (D07, enabled): `success-500` `#16A34A` background (pressed `success-600` `#15803D`) — the one action that begins active driving state, uses the success/green semantic, not primary
- `Go online` (D06, disabled/blocked state): `neutral-200` `#E5E7EB` background, `neutral-500` `#6B7280` text/icon — greyed, non-interactive
- `Switch vehicle` (D07), `Log out` (D03): outlined pill, `neutral-300` `#D1D5DB` border, `neutral-800`/`danger-600` text respectively — no fill

**Two additional semantic colors are already locked in `colors.js` and used pervasively for status
communication — declare both, not just destructive:**

| Semantic | Value | Reserved for |
|----------|-------|---------------|
| `success` (green) | `#16A34A` / tint `#F0FDF4` / `#166534` text | Approved-document status discs, "Active"/"Approved" badges, all-clear strips (D07 "All 5 documents approved"), `Go online` button fill |
| `warning` (amber) | `#D97706` / tint `#FFFBEB` / `#92400E` text | In-review status discs, "Action needed" context (badge itself is danger-tinted per README, but hub/home warning banners and profile-chip alert dot are amber), missing-document dashed markers use `neutral-300`, not amber |

**Profile-chip alert dot (D06):** amber (`warning-500`) filled pill, 20px, white icon — appears
**only** when verification is outstanding for the driver's identity or active vehicle. When fully
cleared, the dot is absent entirely (not recolored to green) — do not invent a "cleared" dot state.
Online/offline itself is conveyed only via the text label (`<plate> · offline` / `<plate> · online`)
appended after the plate — no color-coded dot for online status in this phase's scope.
