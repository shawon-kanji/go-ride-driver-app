`driver_locations` schema (go-ride-db-schema/migrations/000004) — CRITICAL for reading the result
correctly:
```sql
CREATE TABLE driver_locations (
  id UUID PRIMARY KEY,
  driver_id UUID NOT NULL UNIQUE,   -- <== ONE ROW PER DRIVER, UPSERTED
  latitude DOUBLE PRECISION NOT NULL,
  longitude DOUBLE PRECISION NOT NULL,
  geohash VARCHAR(32) NOT NULL,
  s2_cell_id VARCHAR(32) NOT NULL,
  recorded_at TIMESTAMPTZ NOT NULL,
  created_at TIMESTAMPTZ NOT NULL,
  updated_at TIMESTAMPTZ NOT NULL
);
```
There is a UNIQUE constraint on `driver_id`, so this table does NOT accumulate one row per ping.
Verifying the cadence means watching `recorded_at` / `updated_at` ADVANCE on the driver's single
row, not counting rows. Anyone expecting a growing row count will wrongly conclude broadcasting is
broken.

Tiering implemented in plan 02-05 (`src/features/presence/location-broadcaster.ts`):
```
MOVEMENT_MIN_INTERVAL_MS  = 10_000   // never POST more than once per 10s, even when moving fast
HEARTBEAT_MAX_INTERVAL_MS = 60_000   // always POST at least once per 60s, even when parked
MIN_DISTANCE_METERS       = 25       // ignore sub-25m jitter
```
So a parked device advances `recorded_at` about once a minute; a walking device advances it at most
once every ten seconds.
